## 1. What this is (30-second version)

Grafture turns heterogeneous source files (CSV / Excel / JSON) into a proposed,
AI-reasoned relational schema and exports real migrations. It is **not** another ERD
editor: every competitor (ChartDB, DrawDB, Azimutt) starts from a database you already
have. We start from **raw data you need to integrate**.

**The differentiator — protect it in every change:** _content-aware modeling_. The AI and
the deterministic detectors look at sample values to propose join keys, flag grain
mismatches, and warn about format conflicts (e.g. two ID columns that won't match without
normalization). "AI adds a box to the canvas" is table-stakes; **reasoning about the data
is the product.**

---

## 2. Architecture

pnpm monorepo:

- **`packages/core`** — framework-agnostic TS engine: domain model, zod action protocol,
  parsers, exporters, detectors, the `AiProvider` interface. **No React. No network/server
  code.** MIT.
- **`apps/web`** — the OSS React app: sources panel, canvas, copilot, BYO-key AI, settings,
  home. Depends on `packages/core`. MIT.

The app must stay **fully usable offline with the user's own API key**. Nothing here may
assume a server.

> **Keep `packages/core` React-free and network-free, and keep the whole app server-free.**

## 3. Non-negotiable rules (the done-bar on every task)

1. TypeScript strict. **No `any` at module boundaries.**
2. Every schema mutation goes through core's **`applyActions`** — the single validated path.
   Never mutate diagram state directly. All canvas edits go through the store's typed
   commands so **undo/redo stays correct**.
3. Every AI-emitted action is **validated against the zod action schema** before it touches
   state. Invalid/inapplicable actions are **rejected and surfaced to the user, never
   silently dropped.** (This surfacing _is_ the product's credibility.)
4. `packages/core` stays **React-free and network-free.**
5. Core logic (parsers, exporters, `applyActions`, detectors) ships with **vitest tests.**
6. A task is not done until **`pnpm test`, `pnpm build`, and `pnpm lint` are green.**
7. Work in **small, scoped changes.** Each task names what to **leave untouched.** Don't
   invent behavior unless the task asks for it — the prototype is the behavior reference.

### Domain model (the contract)

`Schema = { tables: Table[], relationships: Relationship[] }`

- `Table = { id, name, x, y, width?, fields: Field[], provenance? }` (`width` is optional
  presentation geometry, resized via the store's `resizeTable` command)
- `Field = { id, name, type, pk: boolean, fk: boolean, provenance? }`
- `Relationship = { id, fromTable, fromField, toTable, toField, cardinality: "1:1"|"1:N"|"N:M", provenance? }`
- `Provenance = { origin: "ai"|"user"|"imported", touched: boolean, rationale? }`,
  `Rationale = { text, evidence: string[], turnId? }` — **optional on every entity**; absent reads
  as user-owned and is never back-filled, so pre-provenance saved projects still load.

Action protocol (zod discriminated union in core, discriminated on `op`). **The `op`
discriminants in `packages/core/src/actions.ts` are the source of truth**; 11 ops on
`main` (the `feat/copilot-intelligence` work merged via PR #18, 2026-07-06):
`add_table | add_field | remove_field | remove_table | rename_table | rename_field |
add_relationship | remove_relationship | set_pk | set_type | set_cardinality`.

Five of them take an optional `rationale` (`add_table`, `add_relationship`, `set_pk`, `set_type`,
`set_cardinality`) and **it is declared first on each** — see the third contract below.

T7 is done: every store command routes through `applyActions`
(`rename_field` was added so manual field renames could too). `add_relationship` now sets
the from-field's `fk` flag and removals clear it when the last relationship on that field
goes away.

### The contracts a new provider / parser / store caller must honor

Each is easy to miss and **breaking** for anyone holding an older mental model. The first two
changed on `chore/rebrand-grafture`; the third landed with provenance (PR #33, 2026-08-01):

- **`AiProvider.propose(schema, sources, message, history, options?: ProposeOptions)`**
  (`packages/core/src/ai/provider.ts`). `ProposeOptions = { intent?: "derive" | "chat" }`.
  The intent is **caller-declared, never inferred from history length**: `"derive"` (a fresh
  New-Project draft) is what gates the investigation phase, where `submit_schema_response` is
  withheld for the first rounds so the model spends them on `probe_join`/`inspect_source`
  evidence. A plain first-turn question is `"chat"` and keeps submit from round one — get this
  wrong and ordinary questions get forced through investigation. All three providers implement it.
- **`parseSource()` / `parseJson()` return `Source[]`, not `Source`** — one JSON file yields a
  parent plus one child per array-of-objects field. Consumers must handle N sources per file
  (`addSources` = one undo step; the sources panel groups children under their parent).
- **`AiProviderResult` carries an optional `notice`** — an out-of-band note from the _provider_
  (not the model) about how a turn was produced, e.g. a local model that fell back to JSON mode.
  It rides beside the reply through `LoopStep` → `ChatMessage` and renders as its own chip; it is
  deliberately kept OUT of `reply`, because `buildConversationHistory` replays assistant `text`
  and a provider note must never come back as the model's own words. New provider surfaces that
  degrade silently should use it rather than polluting the reply.
- **`applyActions(schema, actions, opts?)` — `opts.actor: Origin` is now how provenance gets
  written**, and the store mirrors it as `runActions(raw, { actor, turnId })`. Core cannot infer
  the actor when manual edits and copilot output share one function, so **every caller declares
  it**: copilot `"ai"`, `buildFromSource` `"imported"`, everything else the `"user"` default. A
  new call site that forgets it silently attributes AI work to the user. `turnId` groups a
  copilot turn's rationales in the review panel and is set only on the copilot path. Rules that
  fall out of this and must not be "simplified" away: a rationale from a non-AI actor is
  **dropped** (a reason attached to a hand edit is the user narrating their own work, and nothing
  reads it); `touched` is monotonic; writing a rationale clears `touched` and must run _after_
  `markTouched`; an entity with no provenance is left alone rather than back-filled.
- **`ParseError` carries `sourceName` separately and its `message` never names the file**
  (`packages/core/src/parse/errors.ts`). Callers already know which file they handed us and most
  render it adjacently — an embedded name produced `broken.json: Unable to parse JSON in
"broken.json"`. Aggregating callers compose the two themselves.

### Commands

`pnpm install` · `pnpm dev` · `pnpm test` · `pnpm lint` · `pnpm build`
